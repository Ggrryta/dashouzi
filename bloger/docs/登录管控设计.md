# 登录管控设计文档

> 核心 JWT 是无状态的：token 自身（签名 + exp）就是全部真相。
> 所有登录管控的本质，都是在无状态 JWT 之外**引入一层外置状态**，由离散事件触发状态转化，由鉴权逻辑读取并判断。
>
> 一句话：**无状态换来扩展性，有状态换来控制力，管控就是在两者之间按需"借"状态回来。**

---

## 一、方案总览

引入外置状态有 4 种粒度，从粗到细：

| 方案 | 外置存储 | 查询频率 | 粒度 | 能力范围 |
|------|---------|---------|------|---------|
| 方案 A：Token 版本号 | 用户表 1 个字段 | 每请求查用户表 | 最粗（全用户） | 改密码 / 封号一次性失效 |
| 方案 B：黑名单 | Redis（jti → 标记） | 每请求查 1 次 | 中（单 token） | 主动登出 / 单 token 吊销 |
| 方案 C：会话白名单 | Redis（session 表） | 每请求查 1 次 | 最细（单会话） | 设备管理 / 远程登出 / 单设备登录 |
| 方案 D：双 Token | Redis（refresh） | 每 15min 查 1 次 | 中（refresh 维度） | 会话续期 + 可控吊销 |

**控制力与外置查询频率成正比**：越精细的管控，每个请求要查的外置状态越多。方案 D 之所以是业界主流，是因为它把查询频率从"每请求"降到"每 15 分钟一次"，把控制力成本摊薄了。

---

## 二、方案详解与伪代码

### 方案 A：Token 版本号

**原理**：用户表加 `token_version int` 字段，签发时写入 claims，鉴权时与库中当前版本比对。任意"让该用户全部 token 失效"的事件，只需 `token_version++`。

**状态转化**：
- 签发：`claims.token_version = user.token_version`
- 事件（改密码 / 封号）：`UPDATE users SET token_version = token_version + 1 WHERE id = ?`
- 鉴权：`claims.token_version == user.token_version ?` 放行 : 拒绝

**关键校验伪代码**：

```go
// 签发
func (j *JWT) GenerateToken(user *User) (string, error) {
    claims := Claims{
        UserID:       user.ID,
        Role:         user.Role,
        TokenVersion: user.TokenVersion, // ← 关键：快照当前版本
        RegisteredClaims: jwt.RegisteredClaims{
            ExpiresAt: jwt.NewNumericDate(time.Now().Add(j.expire)),
            // ...
        },
    }
    return jwt.NewWithClaims(jwt.SigningMethodHS256, claims).SignedString(j.secret)
}

// 鉴权中间件（每请求查一次用户表）
func Auth(userRepo UserRepo, j *jwt.JWT) gin.HandlerFunc {
    return func(c *gin.Context) {
        claims := parseAndVerify(c, j) // 原有签名+过期校验
        if claims == nil { return }

        // ← 关键：比对版本号
        user, err := userRepo.GetByID(claims.UserID)
        if err != nil || user.TokenVersion != claims.TokenVersion {
            response.Error(c, errcode.ErrTokenRevoked) // 版本对不上 = 旧 token
            c.Abort()
            return
        }
        c.Set("user_id", claims.UserID)
        c.Next()
    }
}

// 改密码 / 封号 handler
func ChangePassword(c *gin.Context) {
    // ... 校验旧密码、写新密码 ...
    userRepo.IncrTokenVersion(user.ID) // ← 一次让该用户所有 token 失效
}
```

**适用**：改密码、找回密码、管理员封号——这类"让此人所有 token 立即失效"的场景。
**局限**：粒度粗，无法只踢某个设备；每请求都要查用户表。

### 方案 B：黑名单（jti + Redis）

**原理**：每个 token 带唯一 `jti`，登出时把 `jti` 写入 Redis 黑名单，TTL = token 剩余有效期。鉴权时检查 `jti` 是否在黑名单。

**状态转化**：
- 签发：`claims.jti = uuid()`，同时可记录 `user:{id}:jtis` 集合便于按用户批量拉黑
- 事件（登出）：`SET blacklist:{jti} 1 EX {剩余TTL}`
- 事件（踢人）：遍历 `user:{id}:jtis`，批量写入黑名单
- 鉴权：`EXISTS blacklist:{jti} ?` 拒绝 : 放行

**关键校验伪代码**：

```go
// 签发
func (j *JWT) GenerateToken(user *User) (string, error) {
    jti := uuid.NewString()
    claims := Claims{
        UserID: user.ID,
        RegisteredClaims: jwt.RegisteredClaims{
            ID:        jti, // ← jti
            ExpiresAt: jwt.NewNumericDate(time.Now().Add(j.expire)),
        },
    }
    token, _ := jwt.NewWithClaims(jwt.SigningMethodHS256, claims).SignedString(j.secret)
    // 记录到用户的 jti 集合，便于按用户批量吊销
    rdb.SAdd(ctx, "user:"+user.ID+":jtis", jti)
    return token, nil
}

// 鉴权中间件（每请求查一次 Redis）
func Auth(rdb *redis.Client, j *jwt.JWT) gin.HandlerFunc {
    return func(c *gin.Context) {
        claims := parseAndVerify(c, j)
        if claims == nil { return }

        // ← 关键：查黑名单
        if n, _ := rdb.Exists(ctx, "blacklist:"+claims.ID).Result(); n > 0 {
            response.Error(c, errcode.ErrTokenRevoked)
            c.Abort()
            return
        }
        c.Set("jti", claims.ID)
        c.Set("exp", claims.ExpiresAt.Unix())
        c.Next()
    }
}

// 主动登出
func Logout(c *gin.Context, rdb *redis.Client) {
    jti := c.GetString("jti")
    exp := c.GetInt64("exp")
    ttl := time.Until(time.Unix(exp, 0))
    if ttl > 0 {
        rdb.Set(ctx, "blacklist:"+jti, "1", ttl) // ← 拉黑该 token
    }
    rdb.SRem(ctx, "user:"+userID+":jtis", jti)
    response.Success(c, nil)
}

// 管理员踢人（批量拉黑某用户所有在线 token）
func KickUser(userID string, rdb *redis.Client) {
    jtis, _ := rdb.SMembers(ctx, "user:"+userID+":jtis").Result()
    pipe := rdb.Pipeline()
    for _, jti := range jtis {
        pipe.Set(ctx, "blacklist:"+jti, "1", maxTTL) // 用最大剩余 TTL
    }
    pipe.Del(ctx, "user:"+userID+":jtis")
    pipe.Exec(ctx)
}
```

**适用**：主动登出、单 token 吊销、管理员按用户踢下线。
**局限**：只能做"吊销"，管不了"单设备登录"；每请求多一次 Redis 查询。

### 方案 C：会话白名单（session_id + Redis/DB）

**原理**：服务端维护有效会话表，token 带 `session_id`，鉴权时查表确认会话是否仍有效。这是能力最强的方案，能管理设备列表、远程登出、单设备登录、设备数上限。

**Redis 结构**：

```
session:{sid}  →  Hash { user_id, device, ip, login_at, expire_at }
user:{uid}:sessions → Set { sid1, sid2, ... }   # 该用户所有有效会话
```

**状态转化**：
- 签发（登录）：创建 session 记录，加入用户会话集合
- 事件（登出 / 远程登出）：删除 `session:{sid}`，从集合移除
- 事件（单设备登录）：删掉该用户所有旧 session
- 鉴权：`EXISTS session:{sid} ?` 放行 : 拒绝

**关键校验伪代码**：

```go
// 登录（创建会话）
func Login(c *gin.Context, rdb *redis.Client, j *jwt.JWT) {
    // ... 校验账号密码 ...
    sid := uuid.NewString()
    now := time.Now()
    session := map[string]interface{}{
        "user_id":  user.ID,
        "device":   c.Request.UserAgent(),
        "ip":       c.ClientIP(),
        "login_at": now.Unix(),
    }
    rdb.HSet(ctx, "session:"+sid, session)
    rdb.Expire(ctx, "session:"+sid, j.expire)
    rdb.SAdd(ctx, "user:"+user.ID+":sessions", sid)

    token, _ := j.GenerateToken(user, sid) // claims 带 session_id
    response.Success(c, gin.H{"token": token})
}

// 鉴权中间件（每请求查一次 Redis）
func Auth(rdb *redis.Client, j *jwt.JWT) gin.HandlerFunc {
    return func(c *gin.Context) {
        claims := parseAndVerify(c, j)
        if claims == nil { return }

        // ← 关键：查会话是否还存在
        if n, _ := rdb.Exists(ctx, "session:"+claims.SessionID).Result(); n == 0 {
            response.Error(c, errcode.ErrSessionInvalid)
            c.Abort()
            return
        }
        c.Set("session_id", claims.SessionID)
        c.Next()
    }
}

// 主动登出（删自己会话）
func Logout(c *gin.Context, rdb *redis.Client) {
    sid := c.GetString("session_id")
    uid := c.GetString("user_id")
    rdb.Del(ctx, "session:"+sid)
    rdb.SRem(ctx, "user:"+uid+":sessions", sid)
}

// 单设备登录：新登录时踢掉该用户所有旧会话
func LoginSingleDevice(c *gin.Context, rdb *redis.Client, j *jwt.JWT) {
    // ... 校验账号密码 ...
    // ← 关键：先删旧会话
    oldSids, _ := rdb.SMembers(ctx, "user:"+user.ID+":sessions").Result()
    pipe := rdb.Pipeline()
    for _, sid := range oldSids {
        pipe.Del(ctx, "session:"+sid)
    }
    pipe.Del(ctx, "user:"+user.ID+":sessions")
    pipe.Exec(ctx)
    // 再创建新会话（同 Login）
    // ...
}

// 设备数上限：登录时检查数量，超限踢最早的
func LoginWithDeviceLimit(c *gin.Context, rdb *redis.Client, maxDevice int) {
    // ... 校验账号密码 ...
    sids, _ := rdb.SMembers(ctx, "user:"+user.ID+":sessions").Result()
    if len(sids) >= maxDevice {
        // 按 login_at 排序，踢掉最早的
        earliest := pickEarliestSession(rdb, sids)
        rdb.Del(ctx, "session:"+earliest)
        rdb.SRem(ctx, "user:"+user.ID+":sessions", earliest)
    }
    // 创建新会话
    // ...
}

// 远程登出某设备（查设备列表 → 删指定会话）
func ListDevices(userID string, rdb *redis.Client) []DeviceInfo {
    sids, _ := rdb.SMembers(ctx, "user:"+userID+":sessions").Result()
    var devices []DeviceInfo
    for _, sid := range sids {
        info, _ := rdb.HGetAll(ctx, "session:"+sid).Result()
        devices = append(devices, DeviceInfo{
            SessionID: sid,
            Device:    info["device"],
            IP:        info["ip"],
            LoginAt:   info["login_at"],
        })
    }
    return devices
}
```

**适用**：社交/金融类需要精细会话管理的系统——设备列表、远程登出、单设备登录、设备数上限。
**局限**：每请求查 Redis，等于把 JWT"退化"成接近 session 模式，损失无状态优势。

### 方案 D：双 Token（Access + Refresh）

**原理**：不直接管控 access token，而是用短命 access（无状态、不查库）+ 长命 refresh（有状态、存 Redis）组合，把管控点放在 refresh 上。

```
access_token:  有效期 15 分钟，纯无状态，每个请求不查库
refresh_token: 有效期 7 天，存 Redis，过期或被删则需重新登录
```

**状态转化**：
- 登录：签发 access + refresh，refresh 存 Redis（`refresh:{rtid} → uid`）
- 事件（登出 / 踢人 / 改密码）：删 Redis 里的 refresh
- 续期：access 过期 → 用 refresh 换新 access（refresh 仍有效则续签）
- 鉴权：access 纯无状态校验；换 token 时才查 refresh

**关键校验伪代码**：

```go
// 登录
func Login(c *gin.Context, j *jwt.JWT, rdb *redis.Client) {
    // ... 校验账号密码 ...
    accessToken, _ := j.GenerateAccessToken(user)  // 15min, 无状态
    rtid := uuid.NewString()
    refreshToken, _ := j.GenerateRefreshToken(user, rtid) // 7d
    rdb.Set(ctx, "refresh:"+rtid, user.ID, 7*24*time.Hour) // ← refresh 有状态
    response.Success(c, gin.H{"access": accessToken, "refresh": refreshToken})
}

// 鉴权中间件（access 纯无状态，不查库）
func Auth(j *jwt.JWT) gin.HandlerFunc {
    return func(c *gin.Context) {
        claims := parseAndVerify(c, j) // 仅签名 + 过期校验
        if claims == nil { return }
        c.Set("user_id", claims.UserID)
        c.Next()
    }
}

// 续期：access 过期后用 refresh 换新 access
func Refresh(c *gin.Context, j *jwt.JWT, rdb *redis.Client) {
    rt := c.PostForm("refresh_token")
    claims, err := j.ParseRefreshToken(rt)
    if err != nil {
        response.Error(c, errcode.ErrInvalidRefresh)
        return
    }
    // ← 关键：查 refresh 是否还在 Redis（被删=已登出/被踢）
    if uid, err := rdb.Get(ctx, "refresh:"+claims.Rtid).Result(); err != nil || uid != claims.UserID {
        response.Error(c, errcode.ErrRefreshRevoked)
        return
    }
    newAccess, _ := j.GenerateAccessToken(&User{ID: claims.UserID})
    response.Success(c, gin.H{"access": newAccess})
}

// 登出（删 refresh，access 自然过期最多 15min）
func Logout(c *gin.Context, rdb *redis.Client, j *jwt.JWT) {
    rt := c.PostForm("refresh_token")
    claims, _ := j.ParseRefreshToken(rt)
    rdb.Del(ctx, "refresh:"+claims.Rtid) // ← 管控点
    // access 不处理，容忍最多 15 分钟窗口
}

// 改密码 / 踢人：删该用户所有 refresh
func RevokeAllRefresh(userID string, rdb *redis.Client) {
    // 需额外维护 user:{uid}:refreshes 集合，或用 scan
    rtids := rdb.SMembers(ctx, "user:"+userID+":refreshes").Val()
    pipe := rdb.Pipeline()
    for _, rtid := range rtids {
        pipe.Del(ctx, "refresh:"+rtid)
    }
    pipe.Del(ctx, "user:"+userID+":refreshes")
    pipe.Exec(ctx)
}
```

**适用**：业界最主流方案。用短有效期换"不必每请求查库"，用 refresh 换"可控吊销"。
**局限**：旧 access 在剩余 15 分钟内仍可用（容忍窗口）；refresh 流程增加一次请求往返。

## 三、管控场景 × 方案对照

| 管控场景 | 触发事件 | 状态转化 | 推荐方案 | 容忍窗口 |
|---------|---------|---------|---------|---------|
| 主动登出 | 用户点退出 | 删 session / 拉 jti 黑名单 / 删 refresh | B / C / D | D 有 ≤15min |
| 改密码失效旧 token | 提交新密码 | `token_version++` | A | 无 |
| 找回密码失效旧 token | 重置成功 | `token_version++` | A | 无 |
| 管理员封号/踢人 | 封禁操作 | `token_version++` 或批量拉黑 jti | A / B | 无 |
| 单设备登录 | 新设备登录 | 删该用户所有旧 session | C | 无 |
| 多设备远程登出 | 用户删设备 | 删指定 session | C | 无 |
| 设备数上限 | 新设备登录 | 超限时踢最早 session | C | 无 |
| 会话续期 | access 过期 | refresh 换新 access | D | — |
| 异地登录检测 | 新 IP 登录 | 比对历史 IP → 通知/二次验证 | C + IP 库 | — |

## 四、状态转化通用模型

所有方案都可抽象为同一个状态机：

```
                    ┌─────────────────────────────────┐
                    │          签发 Token              │
                    │  (写入 claims 快照 + 外置状态)    │
                    └────────────┬────────────────────┘
                                 │
                                 ▼
                    ┌─────────────────────────────────┐
          ┌────────│         有效 (Valid)              │────────┐
          │        └────────────┬────────────────────┘        │
          │                     │                              │
   离散事件              每请求鉴权读外置状态              自然过期(exp)
   (登出/改密/踢人)              │                              │
          │                     │ 比对失败?                    │
          ▼                     ▼                              │
   ┌──────────────┐     ┌──────────────┐                      │
   │ 修改外置状态  │────▶│  失效(Revoked)│◀─────────────────────┘
   │ (写黑名单/    │     └──────────────┘
   │  version++/  │
   │  删session)  │
   └──────────────┘
```

**三个角色**：
1. **状态写入端**：离散事件（登录、登出、改密码、封号）触发，修改外置状态
2. **状态读取端**：鉴权中间件每请求执行，读取外置状态并比对
3. **状态载体**：用户表 / Redis / DB，决定粒度与查询成本

## 五、方案选型矩阵

| 需求 | A 版本号 | B 黑名单 | C 会话表 | D 双token |
|------|:-------:|:-------:|:-------:|:---------:|
| 主动登出 | △ 粗 | ✅ | ✅ | ✅(有窗口) |
| 改密码失效 | ✅ | △ 需批量 | ✅ | △ 需批量 |
| 踢人下线 | ✅ 全踢 | ✅ | ✅ 精确 | ✅(有窗口) |
| 单设备登录 | ❌ | ❌ | ✅ | ❌ |
| 设备列表/远程登出 | ❌ | ❌ | ✅ | ❌ |
| 会话续期 | ❌ | ❌ | △ | ✅ |
| 每请求查库 | ✅ 查用户表 | ✅ 查Redis | ✅ 查Redis | ❌ 仅续期查 |
| 实现复杂度 | 低 | 中 | 高 | 中 |

**选型建议**：
- **轻量起步**：A + B 组合，覆盖 80% 需求（改密码 + 登出 + 踢人），每请求一次 Redis `EXISTS`
- **需要设备管理**：升级到 C 会话表
- **高并发 + 可接受短窗口**：D 双 token，把查询频率从"每请求"降到"每 15 分钟"

## 六、项目现状与改造建议

### 现状

项目 `Claims`（`pkg/jwt/jwt.go:23-28`）仅有 `user_id / username / role + 标准声明`：
- 无 `jti`，无法吊销单个 token
- 无 `token_version`，改密码后旧 token 仍有效
- 无 session 管理，不支持设备管控
- 已接入 Redis（`router.go:104` 限流器在用），具备改造条件

### 最小改造成本（覆盖 80% 需求）

采用 **方案 A + 方案 B** 组合：

1. **Claims 加 `TokenVersion` 和 `jti`**
```go
type Claims struct {
    UserID       uint   `json:"user_id"`
    Username     string `json:"username"`
    Role         string `json:"role"`
    TokenVersion int    `json:"token_version"` // ← 新增
    jwt.RegisteredClaims                          // ID 字段即 jti
}
```

2. **用户表加 `token_version` 字段**
```go
type User struct {
    // ...
    TokenVersion int `gorm:"default:0"`
}
```

3. **鉴权中间件加两道校验**
```go
func Auth(userRepo UserRepo, rdb *redis.Client, j *jwt.JWT) gin.HandlerFunc {
    return func(c *gin.Context) {
        claims := parseAndVerify(c, j)
        if claims == nil { return }

        // 校验1：版本号（改密码/封号即时失效）
        user, err := userRepo.GetByID(claims.UserID)
        if err != nil || user.TokenVersion != claims.TokenVersion {
            response.Error(c, errcode.ErrTokenRevoked)
            c.Abort()
            return
        }

        // 校验2：黑名单（主动登出即时失效）
        if n, _ := rdb.Exists(ctx, "blacklist:"+claims.ID).Result(); n > 0 {
            response.Error(c, errcode.ErrTokenRevoked)
            c.Abort()
            return
        }

        c.Set("user_id", claims.UserID)
        c.Set("jti", claims.ID)
        c.Next()
    }
}
```

4. **事件 handler 触发状态转化**
```go
// 改密码 → 版本号 +1
func ChangePassword(...) {
    userRepo.IncrTokenVersion(user.ID)
}
// 登出 → 拉黑 jti
func Logout(...) {
    rdb.Set(ctx, "blacklist:"+jti, "1", ttl)
}
```

改造成本：2 个字段 + 2 道校验，每请求多一次用户查询（可缓存）+ 一次 Redis `EXISTS`，性能影响可忽略。若后续需要设备管理能力，再升级到方案 C。
